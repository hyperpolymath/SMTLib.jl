== 1. Recon — ground truth

=== 1.1 What issue #43 actually is

All 9 red checks on PR #41 are the CI matrix `test (*)` jobs, and all 9 died at
*setup* on the same line of `.github/workflows/CI.yml`:

----
julia-actions/julia-runtest@79a7e100883947123f8263c5f06e6c2fee60dd0c
----

That SHA exists in *no upstream ref* of `julia-actions/julia-runtest`. It
shares a 30-hex prefix with the real v1.9.3
(`79a7e100…c0ea3eb972f`) and then diverges — an orphan/corrupted pin. Every
`test (*)` job therefore *never ran a single test*: this is the
TOOLING-VERSION-INTEGRITY failure class ("a green/red bit cannot distinguish
'passed' from 'never ran'"), not 9 independent test failures. Issue #43's own
text confirms the same 9 were already red on `main` @ `553d49e` (2026-09-20) —
pre-existing, not caused by the citation PR.

=== 1.3 The naming drift — and why it is harmless here

The issue names its checks `test (1.10, ubuntu-latest, x64)` etc. Since PR #45
the arch dimension is gone and the emitted contexts are `test (1.10,
ubuntu-latest)` etc. Per CICD-SIGNAL-DISCIPLINE, a renamed context orphans any
rule requiring the old name. *Checked and clear:* the repo's active rulesets
require exactly one context — `scan / gitleaks` (ruleset "Secret-Scan-Floor").
Nothing requires the old `x64` names, so the rename created *no phantom
requirements*. This must be stated in the closure record (it is the one
non-obvious fact a future reader needs).
